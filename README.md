# Spine 动画研究｜程序化动作规则库

> 2026-11-09 需求与研究设计。尚未实现动画引擎、模型绑定或视频逆向。研究仓库独立于幻真画室三个主仓库，用于验证技术，不上传未经许可的游戏资源。

## 核心理念

**化繁为简，随心而动**：从多个 Spine / Live2D 动画和 GIF / MP4 中观察规律，提炼少量可调节的数学函数与形变模板；让用户选择精选姿势、开关局部动作、调节幅度和速度，而非手工制作大量关键帧。类似着色器用函数生成材质，程序化动画用函数、骨骼和网格产生运动。

目标是**可复用的视觉运动规律**，不宣称反推出原作者真实物理参数或完整工程；样本质量与多样性优先于数量。

## 动作规则库（候选）

| 动作 | 优先方法 | 主要控制量 | 必要数据 |
| --- | --- | --- | --- |
| 眨眼 | 非对称时间曲线、眼睑形变/差分 | 频率、闭合时间、间隔随机性 | 眼睑图层/网格或 3D 形态键 |
| 呼吸 | 低频缓动/正弦 + 胸廓形变 | 幅度、周期、相位 | 胸廓骨骼或网格 |
| 头发/饰物摆动 | 骨骼链、弹簧阻尼、约束 | 刚度、阻尼、延迟 | 分束、权重、锚点 |
| 胸部及其他软组织回弹 | 局部骨骼/形态键 + 阻尼振荡 | 振幅、频率、阻尼、方向、左右相位 | 连续网格、权重、基准姿势 |
| 接触挤压 | 接触约束 + 形态键/局部网格形变 | 接触点、方向、强度、恢复速度 | 接触体、形变模板 |
| 姿势微调与过渡 | 骨骼插值、四元数、IK | 目标姿势、时长、缓动 | 兼容骨架、关节限制 |

最简回弹模型：m x'' + c x' + k x = F(t)。单段画面通常只能估计等效运动频率、衰减、振幅、相位与可见位移，无法唯一求出真实 m/c/k；必须校验视觉效果和变形合理性。

## 研究管线

1. **采集少量合法样本**：优先同一角色的骨骼/网格/动画曲线 + 对应视频；普通 MP4/GIF 作为视觉对照。
2. **拆解**：读取骨骼、插槽、atlas、权重、关键帧、约束；对视频进行时间对齐、运动追踪、轮廓与局部变形估计。
3. **提炼规则**：分离身体主运动和局部延迟/回弹，拟合可解释的曲线与形变范围；记录置信度和遮挡限制。
4. **验证**：在独立测试人物上重建动作，对照原始动画，检查穿模、拉伸、体积失真、接缝和循环衔接。
5. **迁移**：3D 采用骨骼、形态键、约束；2D 采用分层贴图、网格变形、补画遮挡。3D 骨骼投影只能辅助 2D 关节定位，不能自动生成像素图层。
6. **产品化**：精选姿势 + 程序化动作叠加，提供开关、幅度、速度、循环、预览、GIF/MP4 导出；复杂动作允许少量人工校正。

## 优先实验

- **实验 A：眨眼**：用一段真实 Spine idle 的眼睑状态与时间线，验证可复用闭眼曲线。
- **实验 B：局部回弹**：识别身体主运动与局部相对运动，拟合阻尼曲线；同时检查网格而非只画骨骼线。
- **实验 C：姿势过渡**：选同骨架的两种相近姿势，插值数秒，验证自然程度。
- **实验 D：完整角色 GIF**：实际渲染带贴图、网格和约束的角色，支持局部放大、原速/慢速对比；骨骼线 GIF 不算效果验收。

## 边界与存储

- **不以海量动作库替代规则库**；优先每类 2–3 个精选姿势。
- 不保证一个规则能无误适配任意体型、衣装、视角或遮挡。复杂表演仍可能需要关键姿势与手动修正。
- 研究代码、测试数据格式、算法说明可放此仓库；原始游戏 Spine 工程、购买课程、受限贴图、私人成人素材放本地受控目录，不默认提交 GitHub。
- 与幻真画室通过版本化动作预设接口连接；本仓库作为实验室，不额外拆分主产品仓库。
